# 로컬 이미지 생성기 사용 설명서

Anima · Krea 2 · Qwen-Image 2.1 · MOSS-Image(+ Stable Diffusion) 모델을 이 PC에서만 실행하는 한국어 GUI입니다.
프롬프트와 이미지는 인터넷으로 전송되지 않습니다(접속 주소는 `127.0.0.1`, 이 PC 전용).

## 1. 실행과 종료

| 하고 싶은 일 | 방법 |
|---|---|
| 실행 | 바탕화면 **`로컬 이미지 생성기`** 더블클릭 (또는 `<설치 폴더>\이미지생성기_실행.bat`) |
| 열린 창 다시 보기 | 같은 바로가기를 다시 실행 → 서버를 새로 만들지 않고 기존 화면만 엽니다 |
| 종료 | 검은 콘솔 창 닫기, 또는 화면 오른쪽 아래 **앱 종료** |
| 멈췄을 때 복구 | 바탕화면 **`로컬 이미지 생성기 - 종료·복구`** 실행 후 다시 실행 |

- 실행하면 콘솔 창이 열리고, 생성 엔진(ComfyUI)이 준비되면(약 20초) 기본 브라우저에 화면이 열립니다.
- 주소는 보통 `http://127.0.0.1:7860/`입니다. 7860이 다른 프로그램에 쓰이고 있으면 7861, 7862… 로 자동 변경되고 콘솔에 표시됩니다(내부 엔진 포트 8188도 같은 방식).
- 복구 스크립트는 **이 앱이 시작한 프로세스만** 종료합니다(다른 Python/AI 앱은 건드리지 않음).
- 앱이 강제 종료돼도 생성 엔진은 Windows Job Object로 함께 종료됩니다.

## 2. 화면 사용법 (왼쪽 위에서 아래로)

1. **모델 선택**: Anima(애니·일러스트), Krea 2(미적 품질 범용·사진), Qwen-Image 2.1(글자 표현·지시문 편집), MOSS-Image(긴 영어·중국어 묘사, 글자 표현, Apache-2.0), Stable Diffusion SDXL·SD1.5(직접 넣은 체크포인트·LoRA), Stable Diffusion 3.5.
2. **작업 방식**: 지원하지 않는 방식은 줄이 그어져 비활성화되고, 아래에 이유가 표시됩니다.
   - 텍스트 → 이미지
   - 이미지 변환(denoise): 입력 이미지를 바탕으로 변환 강도만큼 다시 그림. 색·배경 같은 내용 변경은 약함
   - 지시문 편집(Qwen 전용): "우산을 파란색으로 바꿔 줘" 같은 자연어 지시로 수정
   - 참조 이미지 조건부 생성: Krea 2 = 화풍 참조, Qwen = 인물·사물 다중 참조
   - 부분 수정(인페인팅, SD 계열 전용): 이미지 위에 칠한 영역만 다시 그림
   - **프리셋**: 기본 / 저메모리 / 고품질 (모델마다 값이 다르며 서로 공유되지 않음)
3. **프롬프트**: 입력한 원문은 그대로 기록됩니다.
   - `한국어→영어 번역`, `프롬프트 보강`은 선택 기능입니다(Krea 2의 텍스트 인코더 Qwen3-VL 4B를 이 PC에서 실행).
   - 실제로 모델에 전달된 최종 프롬프트는 결과 정보의 **"모델에 전달된 프롬프트"**에 표시됩니다.
   - Anima: `권장 품질 태그 자동 추가`(기본 켬)와 `등급 태그`(기본 '지정 안 함')를 고를 수 있습니다.
     - 품질 태그는 Turbo에만 붙습니다. Aesthetic(고품질)에 `masterpiece, best quality`를 붙이면 `safe`·`full body`가 무시되는 현상이 실측되어 붙이지 않습니다.
     - Aesthetic에서 등급을 `safe`로 고르면 네거티브에 `sensitive, nsfw, explicit`, `sensitive`로 고르면 `nsfw, explicit`이 자동으로 더해집니다(모델 카드 권장: 등급 태그를 긍정·부정 양쪽에). 최종 네거티브는 기록에 표시됩니다.
   - 네거티브 프롬프트는 CFG가 1보다 큰 변형(Anima Aesthetic, Qwen Base, MOSS-Image, SD 계열)에서만 켜집니다.
   - **태그 자동완성**: 프롬프트·네거티브 칸에 입력 중인 단어와 맞는 Danbooru 태그(영어 또는 한국어 별칭, 예: `long_h`, `긴 머`, `미쿠`)가 힌트로 뜹니다. ↑↓로 고르고 **Tab·Enter·클릭**으로 입력, Esc로 닫기. 괄호는 `\(`로 자동 이스케이프되고, Anima에서는 작가 태그에 `@`가 붙습니다. 체크박스로 끌 수 있습니다. (태그 데이터: [mengod-hf/danbooru-tags-kr](https://huggingface.co/datasets/mengod-hf/danbooru-tags-kr)의 `danbooru-tags-anima-kr`(Anima용)·`danbooru-tags-comfyui-kr`(그 외 모델용), MIT)
4. **참조 이미지**: 칸을 클릭해 파일 선택 / 끌어다 놓기 / PC 경로 붙여넣기 후 `경로로 불러오기` / 결과 화면의 `참조 이미지로 사용`. 한글·공백 경로도 됩니다.
5. **크기·시드**: 정사각형·가로형·쇼츠 9:16 프리셋. 쇼츠를 고르면 최종 출력이 1080×1920으로 자동 설정됩니다(생성 864×1536 → Lanczos 리사이즈, 생성 원본은 `원본_생성크기` 폴더에 따로 저장). `매번 랜덤`을 끄면 시드가 고정됩니다. `연속 생성`으로 최대 8장을 대기열에 넣습니다.
6. **고급 설정**(접혀 있음): 모델 변형, 스텝, CFG, 샘플러, 스케줄러, Qwen 프리픽스 캐시 위치, 출력 폴더.
7. **생성** (단축키 Ctrl+Enter) / **현재 작업 취소** / 대기열 각 항목의 `취소`.

오른쪽: 진행 상태(단계·스텝), 결과 미리보기와 정보(모델·정밀도·크기·시드·시간·최대 메모리·이미지 검사·저장 위치), `이미지 저장`, `이미지 열기`, `출력 폴더 열기`, `이 설정 다시 불러오기`, 생성 기록, 엔진 관리(모델 메모리 해제·엔진 재시작·앱 종료). 상단 표시줄에는 엔진 상태, 로드된 모델, VRAM, RAM, 대기열이 1초마다 표시됩니다.

### Stable Diffusion (SDXL·SD1.5·SD 3.5)

- **모델 고르기**: `Stable Diffusion (SDXL·SD1.5)` 또는 `Stable Diffusion 3.5`.
  - SDXL 쪽 `고급 설정 → 모델 변형`에는 `models\checkpoints` 폴더의 체크포인트가 자동으로 나타납니다(SDXL Base 1.0 + 직접 넣은 파일).
  - 직접 받은 체크포인트(Civitai 등의 SDXL·SD1.5 계열, Illustrious·Pony 포함): `.safetensors`를 `models\checkpoints`에 넣고 화면을 새로고침하세요. 앱이 파일 머리말만 읽어 SDXL/SD1.5를 자동 구분하며, SD1.5는 기본 크기를 512×768로 맞춥니다.
  - SD2.x·Flux·SDXL Refiner 등 다른 구조는 목록에 나타나지 않습니다(미지원).
  - SD 3.5는 Medium(기본, 2.5B)과 Large FP8(고품질, 8B, 느림) 두 가지입니다.
- **LoRA**: `models\loras`에 `.safetensors`를 넣으면 `LoRA (선택)` 칸에 나타납니다. 모든 모델(Anima·Krea 2·Qwen-Image 2.1·MOSS-Image·SDXL·SD1.5·SD 3.5)과 모든 모드(이미지 변환·편집·참조·인페인팅 포함)에서 쓸 수 있습니다. 최대 3개, 각각 강도(-2~2)를 정합니다. 앱이 파일 내용으로 계열을 판별해 지금 모델에 맞는 LoRA만 보여 줍니다(SDXL에는 SDXL LoRA, SD1.5에는 SD1.5 LoRA, Krea 2에는 Krea 2 LoRA, Qwen-Image 2.1에는 2.1용 LoRA, MOSS-Image에는 MOSS LoRA 등. 판별하지 못한 파일은 모든 모델에 보이며 맞지 않으면 효과가 없습니다). Anima·SDXL·SD1.5·SD 3.5 LoRA는 모델과 텍스트 인코더에 함께, Krea 2·Qwen-Image 2.1·MOSS-Image LoRA는 모델에만 적용됩니다. Flux.1 LoRA와 Qwen-Image 1.x(20B)용 LoRA는 구조·크기가 달라 쓸 수 없고, SD 3.5 Medium용과 Large용 LoRA도 서로 호환되지 않습니다(SD 3.5는 고른 변형에 맞는 LoRA만 보이며, 예: Large용 LoRA는 Large 변형을 골랐을 때만 나타납니다. 크기를 판별하지 못한 SD3.x LoRA는 두 변형 모두에 보입니다). 공식 예제 `sd_xl_offset_example-lora_1.0`이 함께 설치됩니다.
- **부분 수정(인페인팅)**: 작업 방식 `부분 수정 (인페인팅)` → 이미지 1장을 넣으면 아래에 편집 화면이 나옵니다.
  - `브러시`로 고칠 곳을 칠하고(분홍색 표시), `지우개`로 덜어내고, `모두 지우기`로 초기화합니다. 브러시 크기는 슬라이더로 조절합니다.
  - 프롬프트에는 칠한 곳에 들어갈 내용을 씁니다(예: "a bright blue vintage car").
  - `변환 강도` 1.0 = 칠한 곳을 새로 그림, 낮출수록 원래 모양을 더 유지합니다.
  - 칠하지 않은 영역은 원본 픽셀 그대로 합성됩니다. 생성 크기는 입력 이미지 비율을 따라 약 1MP(SD1.5는 약 0.4MP)로 자동 조정됩니다.
  - `이 설정 다시 불러오기`로 인페인팅 설정을 불러오면 칠한 영역은 다시 칠해야 합니다.
- 지시문 편집·참조 이미지 생성은 SD 계열에서 지원하지 않습니다(별도 모델·어댑터 필요). 인페인팅은 SD 계열에서만 지원합니다.

### 생성 기록 삭제
- **하나씩**: 생성 기록 썸네일 오른쪽 위의 **✕** → 확인 창에서 `삭제`
- **전체**: 생성 기록 제목 옆 **전체 삭제** → 확인 창에서 `삭제` (`취소`나 Esc로 중단)
- **`이미지 파일도 휴지통으로 이동`**(기본 꺼짐)
  - 끄면: 기록만 지우고 이미지 파일은 출력 폴더에 남깁니다.
  - 켜면: 결과 이미지, 생성 원본, 입력 사본을 **Windows 휴지통**으로 옮깁니다(복원 가능). 다른 기록이 아직 쓰는 입력 사본은 남깁니다.
- 탐색기에서 이미지를 직접 지운 기록은 썸네일에 "파일 없음"으로 표시되며, ✕로 기록도 지울 수 있습니다.
- 기록 삭제는 되돌릴 수 없습니다(`app\data\history.jsonl`에서 제거). 삭제 내역은 `logs\app_events.jsonl`에 남습니다.

## 3. 저장 위치

- 결과 이미지: 기본 `<설치 폴더>\outputs` (고급 설정에서 변경 가능)
  - 파일명 `날짜_시간_모델_방식_시드.png`, PNG 안에 설정 정보(`llmimagetest` 텍스트 청크) 포함
  - `입력_이미지\` : 사용한 참조 이미지 사본, `원본_생성크기\` : 최종 크기와 다른 경우의 생성 원본
- 생성 기록: `<설치 폴더>\app\data\history.jsonl`
- 설정: `<설치 폴더>\app\data\settings.json`
- 로그: `<설치 폴더>\logs\comfyui.log`(엔진), `logs\app_events.jsonl`(작업·전환·오류)

## 4. 권장 사용법

- 기본 프리셋 1024px로 시작하세요. 참고로 RTX 4060 Ti 8GB·RAM 32GB PC에서 두 번째 생성부터 Anima ≈ 15초, Qwen Turbo ≈ 15~20초, Krea 2 ≈ 35~47초였습니다(그래픽카드에 따라 다름). MOSS-Image(25스텝)는 1024² 첫 생성 약 53초(모델 로딩 포함).
- 모델·변형을 바꾸면 이전 모델을 자동 해제하고 새로 불러오므로 첫 장은 더 걸립니다.
- 게임·영상 재생 등 GPU를 쓰는 프로그램이 켜져 있으면 VRAM이 부족해 크게 느려질 수 있습니다. 느리면 그 프로그램을 끄거나 `저메모리` 프리셋을 쓰세요.
- 색·배경을 바꾸려면 Qwen의 **지시문 편집**이 denoise 변환보다 정확합니다.
- 설치하지 않은 모델은 화면에 "(미설치)"로 표시됩니다. 나중에 `설치.bat`을 다시 실행해 추가할 수 있습니다.

## 5. 문제 해결

| 증상 | 조치 |
|---|---|
| 화면에 "엔진 오류" | `생성 엔진 재시작` → 계속되면 종료·복구 바로가기 후 재실행. `logs\comfyui.log` 확인 |
| 생성이 몇 분째 같은 단계 (화면에 '3분 넘게 진행이 없습니다' 표시) | ComfyUI는 한 연산(예: VAE 디코딩) 도중에는 취소가 바로 적용되지 않습니다. `생성 엔진 재시작`을 누르면 해당 작업은 취소로 정리됩니다 |
| "GPU 메모리(VRAM)가 부족합니다" | 해상도 낮추기/저메모리 프리셋, GPU 사용 프로그램 종료, `모델 메모리 해제` |
| "시스템 메모리가 부족합니다" | 다른 프로그램 종료. 반복되면 Windows 가상 메모리 확대(관리자 설정, 사용자가 직접) |
| 브라우저가 안 열림 | 콘솔에 표시된 주소(예: `http://127.0.0.1:7860/`)를 직접 열기 |
| 실행 시 `'se'은(는) ... 명령이 아닙니다`, 깨진 한글 명령, `Split-Path ... null` 오류 (v1.0.0) | 실행 BAT의 문자 인코딩 문제입니다. v1.1.0 zip을 같은 폴더에 덮어쓰기로 풀면 해결됩니다(모델·설정은 그대로, 재다운로드 없음). |
| 실행 시 "설치된 ComfyUI(0.40.0)가 ... 오래되었습니다" | 새 버전 파일을 덮어쓴 뒤 `설치.bat`을 아직 실행하지 않은 상태입니다. `설치.bat`을 다시 실행하면 ComfyUI를 업데이트합니다(모델·기록·설정 유지). |
| 바로가기 실행 직후 꺼짐 | `이미지생성기_실행.bat`을 직접 실행해 콘솔 메시지 확인 |
| `did not find executable ... python.exe` | `venv\pyvenv.cfg`의 `home`이 `<설치 폴더>\python\cpython-3.13.15-windows-x86_64-none`인지 확인 |

## 6. 설치·추가·삭제

- 설치/모델 추가/이어받기: `설치.bat` 다시 실행 (끝난 단계는 건너뜀)
- 이전 버전에서 업데이트: 종료·복구 바로가기로 끈 뒤 새 zip을 기존 폴더에 덮어쓰기로 풀고 `설치.bat`을 다시 실행합니다. ComfyUI가 v0.43.0보다 오래되었으면(예: 0.40.0) 기존 폴더를 `ComfyUI_old_<버전>`으로 옮겨 두고 v0.43.0을 새로 설치한 뒤, ComfyUI 안의 입력 이미지(`input\`)·사용자 설정(`user\`)·직접 추가한 커스텀 노드 등을 옮기고 고정 버전 패키지를 다시 맞춥니다. 모두 끝나면 백업 폴더를 정리합니다. `models\`·`outputs\`·`app\data\`(생성 기록·설정)는 건드리지 않습니다. ComfyUI가 이미 v0.43.0이면 아무것도 바꾸지 않고, 더 새 버전이거나 버전을 알 수 없으면 그대로 두고 경고만 표시합니다. 바꾸기 전에 무엇을 할지만 보려면: `venv\Scripts\python.exe setup\setup.py --check-comfy`
- 이미 받은 모델: `설치.bat`은 모델 선택 화면에 [설치됨]/[일부 설치됨]을 표시하고, 이미 있는 파일은 SHA256만 확인해 건너뜁니다. 없는 파일은 PC 안의 다른 ComfyUI 설치·이전 설치 폴더·Hugging Face 캐시에서 같은 이름·크기의 파일을 찾아(최대 약 2분) 확인 후 하드링크/복사로 사용하고, SHA256이 다르면 인터넷에서 새로 받습니다.
- 설치 위치: Python·가상환경·ComfyUI·모델이 모두 이 폴더 안에 있습니다(`python\`, `venv\`, `ComfyUI\`, `models\`). 시스템 Python이나 다른 AI 프로그램에는 영향을 주지 않습니다.
- 폴더를 옮긴 경우: 실행 BAT이 Python 경로를 자동으로 맞춥니다. 바탕화면 바로가기는 `설치.bat`을 다시 실행하면 새 위치로 다시 만들어집니다.
- 완전히 지우기: `로컬 이미지 생성기 - 종료·복구` 실행 후 폴더 전체와 바탕화면 바로가기 2개를 삭제하면 됩니다.
